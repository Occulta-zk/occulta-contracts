# Contributing

## The one rule that overrides everything else

**No cryptographic change is merged without a fixture proving it matches the reference
implementation.** "It compiles" and "it looks right" are not evidence. A committed fixture
generated by circomlib (for Poseidon) or snarkjs (for a Groth16 proof/vkey/public-signals
triple) is evidence. See `fixtures/README.md` and `scripts/gen-fixtures.sh`.

This applies to: `occulta-poseidon`'s permutation parameter tables and sponge construction,
`occulta-verifier`'s verification equation and encoding of proof/VK points, and any circuit
public-signal ordering in `apps/*`. It does not apply to `occulta-merkle` or the contract
plumbing (registry storage, event emission), which get property tests instead — see
`README.md`'s testing section.

## Before you open a PR

1. `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace`
   all pass locally.
2. If you touched anything in `docs/PLATFORM.md`'s scope (an SDK method name, byte length, or
   feature flag), re-verify it against the actual crate source — not a blog post, not a
   docs.rs summary, the vendored source in your local Cargo registry cache or the upstream
   repo — and update the citation.
3. If you touched a public-signal order anywhere, add the permutation test described in the
   build spec (§5): swap two signals, assert verification fails.
4. If you're on Windows with Git Bash: the MSVC toolchain's `link.exe` gets shadowed by Git
   Bash's own coreutils `link.exe` on `PATH`, producing a confusing "extra operand" error that
   looks nothing like a real MSVC linker error. Either build from PowerShell/cmd, or use the
   GNU toolchain: `rustup run stable-x86_64-pc-windows-gnu cargo test`.

## Never do these (build spec §11)

- Don't write your own pairing, field, or curve arithmetic. Use the host functions.
- Don't implement Poseidon's permutation in Rust "as a fallback." If the host function is
  unavailable, the contract does not run.
- Don't use `temporary()` storage for anything security-relevant (nullifiers, roots).
- Don't add features not in the build spec.
- Don't mark anything production-ready, audited, or mainnet-safe.
- Don't vendor circomlib constants without citing the exact source file and commit.
- Don't silently change a public-signal order, ever.

## Commit style

Small, reviewable units. Every commit should leave `cargo test` green — don't split a
feature across commits such that an intermediate one fails.
